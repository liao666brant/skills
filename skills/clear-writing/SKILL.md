# 清晰写作

本页规则适用于所有文本写作与文案审查。按请求起草、局部修改、润色或审查，沿用读者、输入、格式、范围与已有授权。局部修改保留未受影响的措辞、结构和理由；只读审查交付问题、位置与依据。

## 按需参考

按文本用途选择，不只看扩展名或谁可能读到它；混合文档按段落职责组合规则。已读且仍适用的资料可复用。

- README、文档结构、标题、注释、报告、演示、导出、界面文案，以及事实归属或时效性：[人类文档与文案](references/human-writing.md)。
- CLI 帮助、错误、状态、诊断、机器输出，以及行为变更后的文案同步与测试：[产品输出与同步](references/product-output.md)。
- Agent 文档，包括 Skill、AGENTS.md、CLAUDE.md 和引用的执行说明或纯参考资料：[Agent 文档](references/agent-writing.md)。
- 创建或编辑 Skill 时，同时读取 [Skill 机制](references/skill-mechanics.md)，核对触发、调用策略和路由。

普通写作不涉及上述分支时只应用本页，不因此启动文档重组、仓库扫描或全面审计。

## 保留事实与契约

- 事实、原意、目标语气、作者个性与执行契约优先于文风。保留“必须、仅当”等强度、条件、例外、授权、恢复和完成标准；用户可见文字必须符合实际行为。
- 名称、参数、路径、URL、代码、直接引语及机器格式中的有义字符保持准确；表达规则只作用于可编辑的自然语言。
- 一项含义只维护一处，其他位置给出有用途的文件、符号、键或标题指针；独立分发保留必要的自包含内容。影响决策的现值先核实来源，长期文档记录查询入口。
- 简短回复也保留排错和核验所需的已知证据，如退出码、失败条件、是否产生副作用。进度只说明新增事实、阻塞或决定；最终回复给结果和必要证据，不重复铺陈过程。

## 表达检查

扫描下列模式，重写范围内的问题段落，再核对事实、原意与语气。它们是判断规则，不是关键词替换器。

### 内容与用词

- 拔高、宣传和悬空评价改为实际事实或机制；“凸显、确保、促进”未增加信息时删掉。来源应相关且说明其内容，不堆机构名号；模糊的“专家认为”要补来源，否则删除归因和无依据结论。
- “尽管面临挑战仍蓬勃发展”写成具体挑战与结果。泛泛美好结论改为已有事实或计划，不补编计划。真实未知且影响行动时明确说明，不用“具体信息有限”填充篇幅。
- 优先普通词，留意“赋能、至关重要、格局、画卷、深入探讨”等套词；确有准确含义时保留。“作为……存在、堪称、拥有着”通常直接写“是、有”。“为了能够、由于……这一事实、需要特别指出”等短语压缩或删除。
- 同一对象用一个准确称呼，保留必要的术语重复。直接写重点，删“不仅 X，更 Y”等固定对比；不强凑三点，“从 X 到 Y”须属同一尺度，否则直接列主题。
- 技术隐喻回到普通名词和实际机制，不能用新行话解释旧行话。留意 substrate、wedge、vector、locus、vantage、nexus、primitive、harness、surface、bedrock、scaffolding、modality、paradigm、gold-plating、ratchet、endgame、north star、flywheel；词有精确领域含义时保留。
- 用可验证的事实、数字或动作代替“数据库触手可及”等感觉表达，例如“`.toSQL()` 返回实际发送的 SQL”。有直说就不用警句口号、刻意断句、代码拟人、比喻动词或固定铺垫；无内容的句子删除。

### 句子与样式

- 一句一个主要意思，需要回读时拆句或删从句。执行者已知且重要时优先主动语态。用准确动词减少副词；“更快、显著提升”等需要适用的测量结果。
- 不以缺主谓的碎片、符号串或含糊缩写代替完整句子。保留真实不确定性，将“可能潜在地也许”等多重保留压成与证据相称的一层。
- 自然语言不使用破折号，也不用括号、短横线或连接号替代破折号停顿，改用句号或逗号。代码、参数、复合词和标识符中的连字符保留。
- 冒号只引出列表或示例，不连接普通句子。粗体帮助定位对象，不遍标术语或缩写；行内引导语须命名对象且后文提供新信息，避免“性能：性能得到提升”。
- 英文标题用 sentence case 并保留专名大小写，英文用直引号；中文标题与引号按文体保留。删除标题和项目符号中的装饰表情。
- 删除客套、讨好和邀约式开头结尾，如“当然可以、问得好、完全正确、希望有帮助、如需要请告诉我”，直接回应内容。

### 作者声音

文章保留有依据的判断、长短句节奏、复杂或矛盾感受、合适的第一人称与适度不规则；写清感受的缘由，不编造经历。操作指南、诊断和指令沿用目标语气，不注入未经表达的立场。规范性规则写清动作，不当作“没有事实”删除。

## 完成与交付

以首次接触问题的读者身份重读，修掉残留套话、信息遗漏和本次引入的问题。描述具体项目的句子若只换项目名就能套用，应补事实或删空话；通用规则、执行约束和个人表达按其职责判断，不能仅因可复用就删。

核对请求、事实、原意、语气、条件与例外，以及读者能否理解或执行。改文件检查 frontmatter、格式和受影响路径、锚点；行为说明按产品输出参考同步。纯文字不跑无关构建；实际输出变更须观察输出并检查，区分已验证与未验证。

交付请求的文本或审查结果，仅附有助决策的解释。不另加固定输入模板、报告格式、总结文件，或扩展成提交、安装与发布。
