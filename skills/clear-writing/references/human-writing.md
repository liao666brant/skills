# 人类文档与文案

用于文档组织、README、界面文案、标题、代码注释，以及报告、演示和导出物。CLI、诊断与行为变更后的同步检查按入口的产品输出分支处理。

## 文档职责与信息顺序

一份文档承担一项职责，例如长期契约、提案、调查、待办、带日期的工作单或运行手册。按读者当前任务决定归属；一页不再服务单一任务时再拆分，保留一行用途和精确链接。

先写范围和权威入口，再写通用规则与主路径，最后写例外、恢复和变更检查。概览只总结稳定语义，不为自包含塞入完整字段表、载荷或当前数值。

README 每章只做一件事：定位不累积功能列表，快速开始不插入架构讨论，详细规范通过链接到达。新增章节前核对段落依附关系，参数表与它的脚注等内容应保持相邻。

## 事实与理由的归属

- 每个事实只有一个规范来源。一同变化的字段、优先级链和支持值集中维护，其他位置保留精确链接和自身增量。两页都称详细规范时，范围广者放共同规则，范围窄者只放差异。
- 完整复述契约后再写“完整说明见……”仍是重复，应留下链接与本页特有内容。独立分发的文件和特定表面所需的补充说明可以合理复制，不应产生不可用的外部依赖。
- 操作指南写如何执行，参考文档写当前契约，设计取舍写进设计记录、ADR 或作出决定的 PR。一次性问答留在回复中。保留理解当前操作确实需要的非显然约束，不在使用页重演选择过程。
- 提醒聚焦最容易遗漏的一项。完整的检查契约应留在实际执行步骤中，不把所有产物重复列成提醒。

## 易过期事实

长期页面承载意图、不变量、边界、流程和失败处理。对变化快于文档的事实，记录如何查询当前答案。

版本和协议号、镜像标签、构建 ID、已部署提交、对象或迁移数量、到期日期、“已上线”或“尚未发布”等状态，放入变更日志、Git 历史或发布工单。必须展示现值时，从权威来源在构建时生成。

指针定位具体文件及可搜索的符号、函数、数据键或标题，而不是“见源码”或仓库根目录。例如指向 `net/constants.py` 中的 `PROTOCOL_VERSION`。如果没有单一符号拥有事实，应指出代码边界问题，不复制一张表来掩盖它。只有事实来自有序文件集或加载器枚举时，才以目录作为目标，并附可搜索的选择键。

仓库说明某个提交的预期行为，运行系统才知道在线提交、健康和实际产物。文档给出查询命令或控制台；合并不能证明部署。部署成功的观测留在对应发布记录。

## 标题、注释与交付物

读者不需要见过原讨论就能理解文本。标题、摘要和注释描述最终行为；中间尝试、放弃方案和临时负向范围留在讨论、Git 历史或审查线程中。

说明性标题点明正文的动作、问题或结果，避免只重复对象名。标题须与实际内容对应，不补出材料未支持的效益。

注释记录无法从代码恢复的原因，例如顺序要求、上游缺陷或平台特性。只有读者确实会考虑某个替代方案时，才解释为何不用它；不要复述代码已经表达的动作。

“推荐”“更快”“更好”“默认安全”等会影响行动的判断，需要自身基准或评估支持，并核对其适用条件。纯粹说明代码行为不需要额外论证；过期的测量值不能继续支持当前选择。

报告、演示、导出和界面传达结论、值及读者需要的说明。制作笔记、作者的方法理由和作者下一步不属于产品正文。帮助文本、空状态和用户明确要求的方法论有其必要说明，不按同一标准删除。发布记录可以写已核实且有时点的状态，但不能把未验证部署说成已上线。

## 修订与审查

保留未受影响的措辞、结构和有价值的区分。检查本次改动是否打断相邻关系、重复规范来源、写入易过期值或掺入会话过程。只读审查指出问题位置、影响及证据，不直接应用修改。
