# 产品输出与同步

用于 CLI 帮助、错误、状态、诊断、机器输出，以及行为变化后的文案与测试。Agent 读取的随包 Skill、插件元数据和工具描述也是使用界面。

用户要求可直接使用的输出时，按请求涉及的场景、表面和输出流交付完整成品，不以展示策略说明代替文本；不编造未提供的命令或字段值。

## 状态与诊断

- 展示实际生效值，回答“现在运行会发生什么”。按运行时的环境变量与分层配置优先级解析，不能只报告某个文件中的存储值。
- 某层配置无法加载时，明确该失败，并使用仍可加载的最完整状态。不要退回空默认值，误报已有凭据或配置缺失；可读取状态不代表应用已经能够正常启动。
- 人类可读的健康检查和诊断只列偏离项及来源；正常值和完整列表属于专门的配置查看输出。同一任务需要两者时，分别交付完整的健康检查块和配置查看块，不能把正常值塞入健康检查，也不把配置查看内容留在说明段中。
- 来源与状态标注精确到实际不同的部分。例如只有 token 来自环境变量时，不把 URL 和模型所在的整个端点块都标成环境变量。
- 加入元数据后重读相邻标签，消除“默认（默认）”等重复。
- 路径、ID 和 URL 必须在窄终端中仍能完整复制。这些载荷行禁用省略和自动裁切。

## 错误与帮助

错误应说明发生什么、发生在哪里、下一步如何处理。按实际输入指出出错文件、被拒字段、允许字段及设置应该放置的位置。错误只提出有依据、可执行的下一步。

明确失败，不静默降级；为了隐藏堆栈而捕获异常时，仍保留原始错误消息。帮助文本、默认值和必填性必须与实际行为一致。

## 机器格式

Porcelain、TSV、JSON 等输出保持既有协议，包括字段、值、顺序要求和应缺失的内容。装饰、提示与注解进入 stderr 或人类可读路径。文风处理不改协议内容，不向 stdout 加解释。

## 行为变更后的同步

实现行为变更、更新行为说明或审查相关差异时，主动搜索受影响的旧措辞。核对顺序为：

1. `--help` 参数说明，尤其默认值与必填性。
2. 集中式消息、字符串模块和命令文档字符串。
3. README 与其他文档。
4. 随包 Skill、插件元数据与 MCP 工具描述。
5. 描述旧行为的路线图和状态说明。

范围内各处一致才算同步完成。标题改名后验证锚点，文件移动后验证相对链接；常规测试通常不能证明这些链接正确。

## 验证输出

涉及输出行为的变更，观察实际输出并运行相关检查。人类文本测试断言扁平化的文本或行为，不依赖控制台排版；约 80 列换行不应导致失败，可在适合的测试中使用 `" ".join(output.split())` 后断言。测试时清除 `FORCE_COLOR` 与 `COLORTERM`，避免 ANSI 转义污染捕获结果。

机器格式应解析验证，并覆盖必须存在和必须缺失的内容。普通文档修订检查内容、格式和链接，不为了锁定措辞增加脆弱测试。
