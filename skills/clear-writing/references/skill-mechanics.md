# Skill 机制

编写 Skill 时读取，处理 frontmatter、发现、调用方式和路由。调用策略会影响常驻上下文成本与人记忆入口的负担，不能仅为减少技能数量或文字而更改既有策略。

## 自动与显式调用

需要 Agent 自主发现，或需要被其他工作流抵达的 Skill，保留可触发的 description，列出真正独立的任务分支；用户仍可显式调用。纯参考型 Skill 可以承载共享事实，但需有自主发现收益来抵消常驻描述成本。

工作流已约定为纯手动时，采用目标宿主支持的显式调用策略，无需用户重复说明。支持对应 frontmatter 的宿主可用 `disable-model-invocation: true`；Codex 可在 `agents/openai.yaml` 设置 `policy.allow_implicit_invocation: false`。按真实宿主能力选择，不假定所有宿主支持同一字段。显式模式的 description 写成面向人的简短用途摘要，无需堆自动匹配关键词。

不同宿主对显式技能的名称、描述或路径暴露方式不同，不能宣称跨宿主零上下文成本。保留用户选定的调用方式；新 Skill 没有显式限制且应由 Agent 发现时，保留自动发现。

## 共享与拆分

在同一维护和分发环境中，多个显式 Skill 共享的参考应放在技能系统之外的普通文件，并指向同一来源。独立安装的技能必须能找到必需资料；分发所需的自包含内容按共同规则处理，不能依赖个人路径或未声明的其他技能。

只有某分支有独立稳定的引导词，确实需要独立触发或被其他工作流调用，才把它拆成自动 Skill。新增常驻描述应带来相应的发现收益。

## 路由

显式 Skill 太多而难以记忆时，可用菜单列出目标和适用条件。宿主若禁止 Agent 或其他 Skill 调用显式目标，路由只能提示用户点名，不能绕过调用限制。

description、正文与宿主展示元数据应描述相同用途。共享规则留在一个维护位置，按调用方式拆分时核对必需资料仍可达。
