**评分标准**

评估 Agent 面向人或其他 Agent 的自然语言输出，包括状态反馈、进度消息、完成摘要，以及拉取请求、审查或任务评论中的文字。不按差异大小或工具输出长度评分；代码注释的篇幅由代码质量评分器评估。从需要了解结果和下一步的接收者角度判断。以下条目是常见模式，并非穷尽清单；其他导致表达详略不当的情况也应纳入判断。

评估：

- **相称性。** 文字篇幅与工作复杂度匹配。拉取请求描述应相对于其说明的差异判断，不能因整段会话的其他反馈简洁，就抵消冗长描述。
- **填充。** 开场复述请求、预告即将做什么、结尾再次描述可见差异，或仅因模板列出就保留无关的可选小节，都属于填充。模板明确要求的小节本身不扣分，但应简洁作答；冗长展开仍属填充。不能只看 Summary、Changes、Verification 等结构是否填满，应看各节实际传达了什么。
- **重复。** 跨消息反复解释同一点，或再次总结此前摘要。
- **夸饰。** 用“全面”“稳健”等套话、过度保留和修饰代替直接陈述。
- **沟通不足。** 长时间没有反馈、完成消息不说明改动或待审事项，或遗漏接收者需要的信息。
- **渠道选择。** 本应通过消息沟通，却生成用户未要求的总结文件。

**理由**

用 1 至 3 句话引用一段有代表性的内容，例如冗长开场、重复摘要或信息不足的完成消息；若判为 `proportionate`，说明其表达为何与工作相称。
